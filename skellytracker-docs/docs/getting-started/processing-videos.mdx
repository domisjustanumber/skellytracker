# Processing Videos

The pipeline API reads no video file. Read the frames with OpenCV. Give each frame to a run in the
running mode `video`. In `video`, the run gets each frame in order. It keeps state from
frame to frame, for example the person box of the previous frame.

## One video

```python
import cv2
import numpy as np
from skellytracker.core.pipelines import Frame, load_pipeline, start_pipeline

config = load_pipeline("yolox-rtmw-wholebody@skellytracker")
capture = cv2.VideoCapture("cam0.mp4")
fps = capture.get(cv2.CAP_PROP_FPS) or 30.0
rows = []

with start_pipeline(config, camera_ids=["cam0"], running_mode="video", execution_provider="cpu", fps=fps) as run:
    frame_index = 0
    while True:
        ok, image = capture.read()
        if not ok:
            break
        result = run.process(Frame(image, frame_index))
        rows.append(result["wholebody"].xy[0])  # (C, 2) for the one person; NaN for a missing point
        frame_index += 1
capture.release()

xy = np.stack(rows)  # (frames, C, 2)
np.save("cam0_wholebody_xy.npy", xy)
print(xy.shape)
```

A camera gives `timestamp_ms` on each of its frames or on none. This example gives none. The run then
uses `timestamp_ms = frame_index × 1000 / fps`. The default of `fps` is 30.0.

## Synchronized videos from more than one camera

Give one camera id for each video. Then call `run.process_batch` with one frame for each camera.
In `video`, each call must hold a frame for each camera of the run.

```python
import cv2
from skellytracker.core.pipelines import Frame, load_pipeline, start_pipeline

videos = {"cam0": "cam0.mp4", "cam1": "cam1.mp4"}
captures = {camera: cv2.VideoCapture(path) for camera, path in videos.items()}
config = load_pipeline("yolox-rtmw-wholebody@skellytracker")

with start_pipeline(config, camera_ids=list(videos), running_mode="video", execution_provider="cpu") as run:
    frame_index = 0
    while True:
        images = {camera: capture.read() for camera, capture in captures.items()}
        if not all(ok for ok, _ in images.values()):
            break  # stop at the end of the shortest video
        frames = {camera: Frame(image, frame_index) for camera, (_, image) in images.items()}
        results = run.process_batch(frames)  # camera id -> the result of that camera
        frame_index += 1
for capture in captures.values():
    capture.release()

print(frame_index, "frames;", {camera: bool(r["wholebody"].present[0]) for camera, r in results.items()})
```

The pipeline `yolox-rtmw-wholebody` is stateful: it uses the points of the previous frame. In `video`,
the batch of a stateful pipeline is the camera count. The run gives the warning
`batch_limited_by_state` at the start. [Multi-Camera Batching](../guides/multi-camera-batching)
explains the batch.

## A folder of images

The command `run` runs a pipeline on the images of a COCO annotations file. It uses one camera and the
running mode `image`. It reads the images in ascending `image_id` order:

```bash
uv run skellytracker run --pipeline yolox-rtmw-wholebody@skellytracker --coco annotations.json --images images/ --out out/ --ep cpu
```

`run` writes the timing file `timing.jsonl` in the `--out` folder. It writes no keypoint file.
The option `--taps <dir>` gives the tap folder. [Timing and Taps](../technical/timing-and-taps)
gives the file formats.

With no `--ep`, `run` uses the recommended EP and prints it. That EP can be a GPU EP.

The exit codes of `run`:

| Code | Meaning |
|---|---|
| 0 | The run is good. |
| 1 | A failure, also an extra or an ONNX file that is absent. |
| 2 | A usage error, a pipeline that is not valid, or an EP key or an EP option that the EP catalog refuses. |
| 3 | The EP is not available. |
| 4 | A session was not created. |
| 5 | The GPU memory is exhausted. |
| 6 | Cancelled. |
