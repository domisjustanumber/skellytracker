# Certifying a System

`skellytracker.certify()` tests the execution providers (EPs) of skellytracker on this system. It
writes a report. It sends nothing.

A GPU EP runs on a GPU only after a reviewed certification report for the EP, the GPU model, the OS
and the version set of this release, or after a passed quick check on this system. See
[The check rule](../core-concepts/execution-providers#the-check-rule).

## The two levels

| Level | What it does |
|---|---|
| `quick` | Shows that a session in the running mode `video` and a session in the running mode `live` start and run on each EP and GPU that has no reviewed pass. It has a hard time limit of 75 seconds. |
| `full` | Runs the checks of `quick`, also on the reviewed pairs. It adds the pipeline timings for 1, 3 and 6 cameras and the JPEG certification. It takes minutes. |

No level installs an EP or downloads a file. The model files and the EP packs must be on the system
before the run. The test frames are a file of the package: 30 JPEG frames.

## Plan, then run

`certify_plan()` gives the plan of a `certify()` call with the same arguments. It loads no GPU
library and downloads nothing. Show the plan to the user, and get the consent of the user before
the run.

```python
import skellytracker

plan = skellytracker.certify_plan("quick")
print(plan["total"], plan["seconds_estimate"])
print(plan["details"]["checks"], plan["details"]["not_run"], plan["details"]["os_known"])
```

- `total` is the count of the checks that will run. `seconds_estimate` is the time estimate.
- `details.checks` names each EP check, one for each EP and GPU.
- `details.not_run` gives each EP that will not run, with its reason code, for example
  `ep-not-installed`.
- `details.os_known` is true when the project has a reviewed pass for the OS of this system.

Then run the check:

```python
import threading

import skellytracker

cancel = threading.Event()
report = skellytracker.certify("quick", progress=print, cancel=cancel)
for check in report["checks"]:
    print(check["name"], check["result"], check["reason"])
print(report["evidence"])
```

- `progress` gets a progress message at most 10 times a second.
- `cancel` is an object with `is_set()`. A set cancel stops the running check within about a second.
- `execution_providers` and `device` select the EPs and the GPUs. With no selection, the run checks
  each GPU EP of this system.
- Do not run `certify()` while a pipeline holds the GPU.

On the command line, `skellytracker-eps certify KEY` runs the level `quick` on one EP:

```sh
uv run skellytracker-eps certify cuda
uv run skellytracker-eps certify cuda --json
```

It exits with 0 when the EP passes on each GPU, 1 when it fails on one, 3 when the EP cannot run on
this system and 6 when cancelled.

## The checks of the level `quick`

Each check runs in its own child process.

| Check | What it does |
|---|---|
| `cpu:video`, `cpu:live` | The CPU reference: the pipeline on the CPU EP in `video`, then in `live`. |
| `<ep>:probe` | A probe session on the EP. |
| `<ep>:video` | The pipeline on the EP in `video`. It compares the results with the CPU reference. |
| `<ep>:live` | The pipeline on the EP in `live`. It compares nothing. |
| `<ep>` | The result for the EP on the GPU: it passes when the probe, `video` and `live` pass. |
| `<ep>:jpeg-decode`, `<ep>:jpeg-preprocess` | `cuda` and `trt-rtx` only: the GPU frame path. A failure stops only the GPU frame path, not the EP. |
| `mediapipe:smoke` | The pipeline `mediapipe-holistic-tasks` in `live`, when no reviewed row covers the MediaPipe version, the Python version and the OS. |

`<ep>` is `<key>@<device>`, for example `cuda@10de-2484-0`. The pipeline of the checks is
`yolox-rtmw-wholebody@skellytracker`.

## The result of a check

| Result | Meaning |
|---|---|
| `pass` | The test passed. |
| `fail` | The test failed. The reason is a fixed code. |
| `not-run` | The test did not run. The reason tells why, for example `models-missing` or `over-budget`. |
| `record-only` | The check only recorded facts, for example a time. |

A failure is always a fixed reason code, never an error text.
[REASON_CODES.md](https://github.com/freemocap/skellytracker/blob/development/skellytracker/REASON_CODES.md)
lists the codes.

## What the run changes on this system

- The report goes to the folder `reports` of the EP store. Its id is a version 4 UUID.
- The result of each EP check that is `pass` or `fail` becomes the local result of the EP on this
  GPU model. The check rule uses it.
- A field-test EP gets the opt-in during its check. The opt-in stays only when the check passes on
  a GPU.

## The report

The report has the format `skellycertify.report/1.5.0`. It holds:

- `checks`: each check, with `name`, `result`, `reason` and `module` (the EP, for example `CUDA`).
- `evidence`: `valid` and `reasons`.
- `summary`: one item for each EP that ran on a GPU. The level `full` adds `benchmark` items with
  `ms_per_frame` and `fps`. The check `mediapipe:smoke` has a `component` item with the name
  `MediaPipe`. It has the result `skipped` with the reason `reviewed` when a reviewed row skips the check.
- `details`: the EPs, the versions and the skipped pairs.

The report holds no path, no host name, no user name, no serial number and no bus address. Read the
report before you send it to anyone.

`skellytracker.pending_reports()` lists the reports that the user did not hand in.
`skellytracker.read_report(report_id)` reads one report. `skellytracker.mark_reports(ids, state)`
sets the state `pending`, `opened` or `covered`.
