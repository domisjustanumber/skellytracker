# Known open items for the exporter overhaul

These items are true on 2026-10-22. The overhaul plan of each exporter must handle them.

| Exporter | Item |
|---|---|
| OpenMMLab-Exporter | It implements these sections on its host side: the `letterbox` resize and the normalization (`onnx_runtime/preprocess.py`: `letterbox`, `make_normalizer`), `selection: nms` with the letterbox unprojection and the box clamp (`onnx_runtime/decode_nms.py`: `NmsDecoder`), and the `fit` resize (`notes/decisions/scripts/rtmo_sidecar_probe.py`: `fit_resize`, the parity probe of OpenMMLab-Exporter 0020). No reference implementation exists for these sections. The overhaul plan must include the [reference-implementation step](../../../model-sidecar/model-addition-workflow/reference-implementations.md#reference-implementations) for each. |
| OpenMMLab-Exporter | It writes RTMO body7 to `detectors/keypoint_detectors/rtmo/body7/` (`rtmo/identity.py`: `FAMILY_BRANCH`). The part folders of the [storage layout](../../../model-sidecar/format/file-layout.md#storage-layout) are `hand`, `face`, `body` and `wholebody`. The overhaul moves the sidecar to `rtmo/body/`. |
| OpenMMLab-Exporter | `Readme.md` links to the spec with a branch URL (`blob/philip/sidecar_implementation/specs/sidecar-spec.md`). `notes/decisions/0009-detector-output-layout-and-decode.md` links to it with a relative path into a sibling checkout. The overhaul names `specs/model-sidecar/sidecar-spec.md` of skellytracker in their place. |
| Roboflow-Exporter | It implements `selection: top_k` on its host side (`onnx_runtime/convert_rf_detr_coco.py`: `_select_topk_multiclass`), and the `stretch` resize (`onnx_runtime/preprocess.py`: `preprocess_to_nchw`). No reference implementation exists for these sections. The overhaul plan must include the reference-implementation step for each. |
| Roboflow-Exporter | The spec has no RF-DETR example. The `stretch`, `top_k` and `class_logits` rules have no example. The overhauled Roboflow-Exporter provides that example through the procedure "How to provide or replace an example" in [Reference examples](../../../sidecar-implementation-plan.md#reference-examples). |
| Ultralytics-Exporter | It writes `schema_version` `v2024.09.1019` (`yolo_sidecar.py`: `SCHEMA_VERSION`). So the YOLO26 [reference examples](../../../model-sidecar/examples/README.md) are written from its code, not copied from its exports (`kind: forecast` in [`inventory.yaml`](../../../model-sidecar/inventory.yaml)). They are replaced when it writes `vNEXT` sidecars. |
| Qualcomm-Exporter, MediaPipe-Exporter | The local hand plans (`Qualcomm-Exporter/plans/hand-pose-export.md` and `MediaPipe-Exporter/plans/hand-pipeline-export.md`) describe the hand re-crop model as `role: [pose_estimator]` with two points, `crop_center` and `crop_scale`. That is the two-keypoint workaround. An ROI refiner is a gap: the overhaul writes an intake and a change proposal in its place. MediaPipe-Exporter holds only that plan today, and it has no git repo (see [A contributor with no git repo](../../../model-sidecar/model-addition-workflow/README.md#a-contributor-with-no-git-repo) in the model addition workflow). |
