The `post.pose.bottom_up` row shows `packed` when an output packs the keypoints into the detection rows. It shows `poses` when an output has the semantic `poses`.

## Implementation status

The Steps column gives the status of each step and the function that implements it. A step is `implemented`, `partial` or `missing`.

The Vectors column counts the cases of the vector file and the verified cases. A case is verified when the file or the case lists `verified_against`. The Examples column counts the reference examples that the section applies to, by their `kind` in `inventory.yaml`. The Rules with a case column counts the `V-` rules of the section that a `failed` case or an `error` case in the vector file of the section names. The Reference column links the reference module of the section. The No model column gives the reason of the user when no model uses the section (`no_model` in `inventory.yaml`).

The Gate column is the coverage backlog. It shows the graduation conditions of a `draft` section that the section status rules of the [spec README](README.md) give. The column does not show the accepted decision entry or a named test in place of vectors. `pass` means that each other condition is true. Else the column lists the open items: `example` (no `kind: export` example and no reason in No model), `vectors` (a numeric case that is not verified, or an algorithm step with no numeric case; an `error` case and a `failed` case do not count) and `rules` (a `V-` rule with no case).
